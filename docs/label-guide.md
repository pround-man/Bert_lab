# 手表指令标签规范 v0.1

这是可行性实验的临时业务口径，不代表某一款手表已经实现所有功能。固定类别共 25 个，不添加 `OTHER`。机器可读定义、每类三语言正反例的权威文件为 `configs/labels.v0.1.json`。

## 标签与边界

| 内部 ID | 标签 | 支持的动作 |
|---:|---|---|
| 0 | `OPEN_SPORT` | 打开运动模式选择页 |
| 1 | `OPEN_SETTINGS` | 打开通用设置页 |
| 2 | `OPEN_HEART_RATE` | 打开心率页，查看已有默认信息，不发起测量 |
| 3 | `OPEN_SLEEP` | 打开睡眠记录页 |
| 4 | `OPEN_ACTIVITY` | 打开每日活动页 |
| 5 | `OPEN_WORKOUT_HISTORY` | 打开运动历史列表 |
| 6 | `OPEN_WEATHER` | 打开默认天气页 |
| 7 | `OPEN_COMPASS` | 打开指南针 |
| 8 | `OPEN_NAVIGATION` | 打开导航入口 |
| 9 | `OPEN_TIMER` | 打开倒计时页 |
| 10 | `OPEN_STOPWATCH` | 打开秒表页 |
| 11 | `OPEN_ALARM` | 打开闹钟列表 |
| 12 | `OPEN_MUSIC` | 打开音乐控制页 |
| 13 | `OPEN_BLUETOOTH` | 开启蓝牙开关 |
| 14 | `CLOSE_BLUETOOTH` | 关闭蓝牙开关 |
| 15 | `OPEN_FLASHLIGHT` | 开启手电筒 |
| 16 | `CLOSE_FLASHLIGHT` | 关闭手电筒 |
| 17 | `ENABLE_DO_NOT_DISTURB` | 开启勿扰模式 |
| 18 | `DISABLE_DO_NOT_DISTURB` | 关闭勿扰模式 |
| 19 | `ENABLE_BATTERY_SAVER` | 开启通用省电模式 |
| 20 | `DISABLE_BATTERY_SAVER` | 关闭通用省电模式 |
| 21 | `ENABLE_ALWAYS_ON_DISPLAY` | 开启常亮显示 |
| 22 | `DISABLE_ALWAYS_ON_DISPLAY` | 关闭常亮显示 |
| 23 | `LOCK_SCREEN` | 锁定屏幕触控，防误触 |
| 24 | `FIND_PHONE` | 查找已配对的手机 |

页面入口与执行动作分开：“打开倒计时页面”有标签；“开始五分钟倒计时”没有支持标签。“开始记录跑步”“播放音乐”“开始秒表计时”“现在测一下心率”也不属于页面入口。`OPEN_BLUETOOTH` 的历史命名明确表示开启开关，仅打开蓝牙设置页不属于该标签。

不支持时间、地点、路线、指定运动、具体歌曲等参数，不能丢弃参数后强行映射。“看曼谷明天的天气”“查看昨天的睡眠记录”“设置七点闹钟”均为 `[]`。如果同时明确请求打开对应页面，只保留那个独立有效的页面请求。

## 完整文本标注

模型输出当前完整文本中最终有效的动作集合，按内部 ID 排序并去重。没有支持的动作时输出 JSON 数组 `[]`，不能输出字符串 `"[]"`。

| 完整文本 | labels |
|---|---|
| 打开蓝牙。 | `["OPEN_BLUETOOTH"]` |
| 打开蓝牙，快把蓝牙打开。 | `["OPEN_BLUETOOTH"]` |
| 别打开蓝牙。 | `[]` |
| 打开蓝牙，算了，不用了。 | `[]` |
| 打开蓝牙，不对，把它关掉。 | `["CLOSE_BLUETOOTH"]` |
| 先打开蓝牙，然后把蓝牙关掉。 | `["OPEN_BLUETOOTH", "CLOSE_BLUETOOTH"]` |
| 打开蓝牙和手电筒，手电筒算了，蓝牙还是要开。 | `["OPEN_BLUETOOTH"]` |
| 打开蓝牙，再设一个七点的闹钟。 | `["OPEN_BLUETOOTH"]` |
| 请打开闹钟列表，再设一个七点的闹钟。 | `["OPEN_ALARM"]` |
| 蓝牙怎么打开？ | `[]` |
| 能帮我把蓝牙打开吗？ | `["OPEN_BLUETOOTH"]` |
| 蓝牙现在开着吗？ | `[]` |
| 我刚才说过“打开蓝牙”，现在只是复述。 | `[]` |
| 昨天我打开过指南针。 | `[]` |
| 打开那个。 | `[]` |

否定不自动产生相反操作；撤回需要依据明确的指代范围处理。未满足条件的未来动作、解释咨询、过去叙述、引用、状态询问、无上下文的代词均不当作立即执行的请求。无上下文的对象不明例只有在能够明确判定无支持请求时才标 `[]`，不能把几个支持标签之间的真实歧义强行归零；后者应拒绝。明确的礼貌疑问句可以是操作请求。

标签集合不表达参数、次数、动作顺序或当前设备状态。因此连续开关可以保留两个标签；重复催促只保留一个标签。不推测硬件执行是否成功。

## 数据比例与来源隔离

每语言训练／验证／测试的合格数量为 3,000／500／1,000。每个集合均为单标签 60%、多标签 20%、零标签 20%。单标签均衡：每类每语言分别 72／12／24 条。300 条试跑每语言 100 条，仅使用训练集固定前缀；其 60 个单标签覆盖全部 25 类，但不要求这 60 条在类别间绝对均分。

多标签以两个标签为主（80%），三个标签占 20%。预留约 15% 的二／三标签组合不进入训练；测试集多标签的 20% 使用这些组合，单独标记 `unseen_combination` 挑战切片。验证集和其余测试多标签使用该语种训练集实际出现的组合，因此可以分别报告常规表现与未见组合表现。固定语种内尽量平衡标签边际覆盖，不要求所有组合等量。多标签还包含部分撤回、第二个请求放在背景之后、重复一个请求等情形。

零标签内部的默认占比可在 `configs/dataset.toml` 修改：

| 零标签场景 | 零标签内部 | 全数据默认比例 |
|---|---:|---:|
| 纯闲聊 `chitchat` | 50% | 10% |
| 纯否定 `negation` | 10% | 2% |
| 全部撤回 `withdrawal` | 10% | 2% |
| 引用 `quoted` | 8% | 1.6% |
| 过去叙述 `past` | 6% | 1.2% |
| 用法／解释／状态咨询 `howto` | 6% | 1.2% |
| 对象不明 `unclear` | 5% | 1% |
| 不支持的参数／执行请求 `unsupported_parameter` | 5% | 1% |

正式数据按上述权重精确分配；较小试跑使用整数近似。语种分别为 `en`、`zh-Hans`、`th`，要求直接生成自然本地表达。模板表达风格和组合池先按 split 分开，每条数据分配独立语义根；重试沿用该根的 `group_id`。未来若派生翻译、改写或最小对照变体，必须继承同组同 split，不能另起来源混入其他集合。

生成标签与 Qwen 独立判断不一致、语义不确定或质量不合格时，样本不得改标签后接纳；删除淘汰文本并保留拒绝元数据，按原配额补生成。所有数据为合成数据和机器审核数据，合成测试结果不能视为真实用户准确率。

改动标签定义、顺序、示例、场景配置或提示词时，应启动新的数据版本／输出目录并重审受影响数据，不得混用已有结果。
