# 2026-09-30 数字标签响应复现与持续补齐修复

历史试跑合格221/300。79个缺口均达到原3次上限。307次 invalid_generation_response 分布为单标签229、多标签78、零标签0。旧日志未保留原响应和细分原因，无法逐条追溯全部失败；本次复现确认了一种与历史模式相符的主要失败原因。

首先以旧提示词请求3个候选，3条结构合法，未触发故障。随后从只读检查点选择一个历史上8/10条格式失败的原始批次，保留原配额和语义种子重放10条：finish_reason=stop，返回10条，11个标签元素为整数，Pydantic labels/string_type 错误11次，8条拒绝、2条零标签通过。复现使用量9004 tokens，缩小探针6145 tokens。

根因：目录同时包含数字id与名称，生成提示词未清楚限定labels元素为名称字符串。修复明确使用catalog NAME字符串、禁止数字ID/数字字符串，并请求JSON对象输出；解析器继续严格拒绝数字标签，不进行转换或标签兜底。补充字段/类型、JSON、漏样本、重复ID、输出截断等不含正文的错误码。

使用修复后的请求重放同一10条配额，生成10/10结构合法（9904 tokens）；独立盲审10/10结构合法、无质量或标签拒绝（7047 tokens）。这不能证明后续所有响应都正确，后续仍逐条校验。上述3+10+10个候选均仅在内存中用于诊断，不写入训练数据或检查点；失败正文不保存。合计4次实际请求，服务端报告32100 tokens。
